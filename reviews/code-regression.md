# Code review, lens: regression, are the answers correct (Olivia, 2026-10-21)

Verdict: the semantics are right for almost every case I tried, and all spec rows I rechecked agree with the spec text. Two real wrong answers: Ignore order misses nested array order, and Tolerance fails on ordinary float noise. **Must-fix: 2. Should: 5. Nice: 2.**

How I checked: I ran the spec tables again with my own script (not the builder's tests): J1-J31 (all agree with the spec), J12, J22-J25, J29-J31, E1-E14 and 30 more bad inputs, 12 array and key cases, 10 number cases, 6 JSON Patch round trips (I applied each patch to A and compared to B with my own RFC 6902 function), plus the browser: speed (P1 203 ms, P2 260 ms, P3 351 ms in Node; 5.3 MB in 309 ms and 35,000 changes with 500 rows in 349 ms in Chrome; 30.6 MB in 1.8 s; Cancel 34 ms; main thread answers in 1-2 ms during a compare). Template rules hold: canonical on every page (Bingemind mode: `https://bingemind.com/json-diff/...`), `_headers` noindex for pages.dev, contact and terms noindex and out of the sitemap, legal pages linked in the footer, 404 page present, no root robots.txt in Bingemind mode (as the brief says), GA and AdSense scripts absent when the IDs are empty (6 requests on load, all own files), no aggregateRating.

| must | diff.js:169-171, serialize.js:`canonical` | **Ignore order ignores nested array order.** `[{"tags":["a","b"]}]` against `[{"tags":["b","a"]}]` with Ignore order gives "removed $[0]" plus "added $[0]". | must | normalize.js:76-84, 120 | **Tolerance is skipped for numbers with more than 15 digits.** `0.30000000000000004` against `0.3` with "allow a difference of 0.0001" gives "changed" and the note "Tolerance not applied to large numbers".
