# Code review, lens: maintainer (Olivia, 2026-10-21)

Verdict: the core (parser, diff, paths, worker) is clean, iterative and well tested, and the browser tests are good. One thing blocks sign-off: the privacy test and the UI test are not part of the release path. **Must-fix: 1. Should: 7. Nice: 3.**

Checked: `npm test` (117 checks pass), `test:perf` (P1 203 ms, P2 260 ms, P3 351 ms, P6 85 ms), `test:network` and `test:ui` (160 checks) against my own build in both normal and Bingemind mode (all pass), XSS probe (tags and handlers in keys, values, key option, ignore text and error text: nothing ran), localStorage blocked (works), 30 MB compare, Cancel (34 ms), worker crash path read. Template leftovers (README, new-tool.sh, screenshots dir, duplicate legal block, build-date, British spelling): one line only, not counted.

| must | package.json:11-15, .github/workflows/pages.yml | `test:network` and `test:ui` are not run by `npm test`, `build:bingemind`, `deploy` or CI. | The page promises "no request carries your data". Spec 5.5 says the network test runs before every release. Nothing enforces it, so a later change (GA on, a new import) can break the promise silently. | Add `test:release` = `npm test && npm run build && npm run test:network && npm run test:ui`. | should | ui.js:976-990, 864 | `S.pending` callbacks (Format, Patch) are lost when `resetWorker()` runs (typing while a compare runs, Cancel).
